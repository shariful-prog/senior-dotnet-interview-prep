# C# Top 20 Interview Questions (Quick Answers)

> Goal: Fast revision. Each question opens with a one-line definition, then the detail — plus a link to the exact section in the detailed C# notes.

## Type System

### 1. What is the difference between value types and reference types?

**Definition:** A **value type** holds its data directly. A **reference type** holds a link to an object stored elsewhere (on the heap).

**Detail:** Assigning a value type copies the data, so the two variables are independent. Assigning a reference type copies only the link, so both variables point at the same object and a change through one is visible through the other. `int`, `bool`, `struct`, and `enum` are value types; `class`, `string`, and arrays are reference types.

:material-file-document-outline: **Deep dive:** [A1 — Value vs Reference Types](../C-Sharp/csharp-type-system.md#a1--value-vs-reference-types-stack-vs-heap)

---

### 2. What is the difference between `var`, `dynamic`, and explicit types?

**Definition:** `var` lets the **compiler** work out the type at compile time. `dynamic` postpones all type checking until **runtime**. An explicit type is one you write yourself.

**Detail:** `var` is still fully type-safe — it costs nothing at runtime and the variable's type never changes. `dynamic` skips compile-time checking entirely, so you lose IntelliSense and typos become `RuntimeBinderException` at runtime.

:material-file-document-outline: **Deep dive:** [A11 — `var`, `object`, and `dynamic`](../C-Sharp/csharp-type-system.md#a11--var-object-and-dynamic)

---

### 3. What are boxing and unboxing?

**Definition:** **Boxing** wraps a value type inside an object so it can be used as a reference type. **Unboxing** pulls the value back out again.

**Detail:** Boxing creates a new object on the heap and copies the value into it, so it costs both an allocation and a copy. It happens quietly — assigning to `object`, assigning to an interface, or adding to an old `ArrayList`. In a hot loop this creates a lot of garbage. Generics exist largely to avoid it.

:material-file-document-outline: **Deep dive:** [A2 — Boxing & Unboxing](../C-Sharp/csharp-type-system.md#a2--boxing--unboxing)

---

### 4. What is the difference between `class`, `struct`, and `record`?

**Definition:** A `class` is a reference type. A `struct` is a value type. A `record` is a type with **value-based equality** generated by the compiler.

**Detail:** Keep structs small and immutable, because they're copied on every assignment. Records give you `Equals`, `GetHashCode`, `ToString`, and `with` expressions for free, which makes them ideal for DTOs and domain values. `record struct` combines both.

:material-file-document-outline: **Deep dive:** [A3 — Struct vs Class](../C-Sharp/csharp-type-system.md#a3--struct-vs-class) · [A4 — Records](../C-Sharp/csharp-type-system.md#a4--records)

---

### 5. What is the difference between `==`, `Equals`, and `ReferenceEquals`?

**Definition:** `==` is a **static, overloadable operator** resolved at compile time. `Equals` is a **virtual method** resolved at runtime. `ReferenceEquals` always compares identity.

**Detail:** Because `==` binds on the declared type, two variables holding the same object can compare differently depending on how they're declared. `Equals` always dispatches to the object's real type. If you override `Equals`, you must also override `GetHashCode` — otherwise dictionaries and sets break.

:material-file-document-outline: **Deep dive:** [A9 — Equality & Identity](../C-Sharp/csharp-type-system.md#a9--equality--identity)

---

### 6. What is the difference between `const`, `readonly`, and `static readonly`?

**Definition:** `const` is fixed at **compile time**. `readonly` is set once per **instance**, at runtime. `static readonly` is set once per **type**, at runtime.

**Detail:** A `const` value gets copied into every assembly that uses it, so changing it means recompiling all consumers — never make a `const` public across assembly boundaries if it might change. `readonly` can be assigned in the field initializer or the constructor, and can hold a value only known at runtime.

:material-file-document-outline: **Deep dive:** [A7 — const vs readonly vs static readonly](../C-Sharp/csharp-type-system.md#a7--const-vs-readonly-vs-static-readonly)

## OOP

### 7. What are encapsulation, abstraction, inheritance, and polymorphism?

**Definition:** **Encapsulation** hides internal state behind a controlled surface. **Abstraction** exposes what something does and hides how. **Inheritance** reuses behaviour from a base type. **Polymorphism** lets one contract have many runtime implementations.

**Detail:** Encapsulation and abstraction are often confused: encapsulation is about *protecting* data, abstraction is about *simplifying* the model you expose. Polymorphism is what makes `IPaymentProcessor` useful — the caller doesn't know or care which implementation it has.

:material-file-document-outline: **Deep dive:** [B1 — The Four Pillars](../C-Sharp/csharp-oop.md#b1--encapsulation-inheritance-polymorphism-abstraction)

---

### 8. What is the difference between an abstract class and an interface?

**Definition:** An **abstract class** is a partly-implemented base type you inherit from — you get only one. An **interface** is a contract a type promises to fulfil — you can implement many.

**Detail:** Use an abstract class when implementations share state and code; use an interface to describe a capability. Since C# 8 interfaces can have default method bodies, but they still can't hold instance state. Rule of thumb: interface for *can-do*, abstract class for *is-a*.

:material-file-document-outline: **Deep dive:** [B2 — Abstract vs Interface](../C-Sharp/csharp-oop.md#b2--abstract-vs-interface--default-interface-methods)

---

### 9. What do `virtual`, `override`, `new`, and `sealed` do?

**Definition:** `virtual` marks a method as replaceable. `override` replaces it. `new` **hides** it instead. `sealed` stops any further overriding.

**Detail:** `virtual` + `override` gives runtime dispatch — the object's real type decides which method runs. `new` is different and catches people out: which method runs depends on the *declared type of the variable*, so the same object behaves differently through a base reference. That's almost always a bug rather than a design choice.

:material-file-document-outline: **Deep dive:** [B3 — virtual / override / new / sealed](../C-Sharp/csharp-oop.md#b3--virtual--override--new--sealed)

---

### 10. Why use generics, and what are generic constraints?

**Definition:** **Generics** let you write code that works over a type parameter (`T`) instead of a fixed type. A **constraint** (`where T : ...`) restricts what `T` can be.

**Detail:** Generics give you type safety and reuse with no boxing and no casting — `List<int>` stores ints directly, `ArrayList` boxes each one. Constraints tell the compiler what `T` can do, so the body can call those members: `where T : class`, `struct`, `new()`, an interface, or a base class.

:material-file-document-outline: **Deep dive:** [C1 — Generic Classes & Methods](../C-Sharp/csharp-generics.md#c1--generic-classes-methods--type-inference) · [C2 — Constraints](../C-Sharp/csharp-generics.md#c2--constraints-where)

## Collections & LINQ

### 11. What is the difference between `IEnumerable`, `ICollection`, and `IList`?

**Definition:** `IEnumerable<T>` can be iterated. `ICollection<T>` adds `Count`, `Add`, and `Remove`. `IList<T>` adds indexing and ordering.

**Detail:** They build on each other, so each one adds capability. Accept the widest type you can in parameters (usually `IEnumerable<T>`) and return the narrowest that genuinely serves the caller. Returning `IEnumerable<T>` also keeps the door open for lazy streaming.

:material-file-document-outline: **Deep dive:** [D2 — Collection Interfaces](../C-Sharp/csharp-collections.md#d2--collection-interfaces)

---

### 12. What does `yield return` do?

**Definition:** `yield return` turns a method into an **iterator** — the compiler rewrites it into a state machine that produces items one at a time, on demand.

**Detail:** Nothing runs until you start enumerating, and execution pauses at each `yield return` and resumes on the next `MoveNext()`. That lets you stream a huge file or even an infinite sequence without holding it all in memory.

:material-file-document-outline: **Deep dive:** [D3 — Iterators (`yield return`)](../C-Sharp/csharp-collections.md#d3--iterators-yield-return)

---

### 13. What is deferred execution in LINQ?

**Definition:** **Deferred execution** means a LINQ query runs when you enumerate it, not when you write it.

**Detail:** This makes queries composable — you can keep adding `Where` and `Select` and nothing happens until a `foreach`, `ToList()`, or `Count()`. The catch: enumerating twice runs the whole query twice, and any variable the query captured is read at execution time, not definition time. Call `ToList()` to lock in the results once.

:material-file-document-outline: **Deep dive:** [E1 — LINQ Fundamentals](../C-Sharp/csharp-linq.md#e1--linq-fundamentals-query-vs-method-syntax)

---

### 14. What is the difference between `IQueryable` and `IEnumerable` in LINQ?

**Definition:** `IEnumerable` runs the query **in memory**. `IQueryable` builds an **expression tree** that a provider translates into something else — usually SQL.

**Detail:** With `IQueryable`, EF Core turns your `Where` into a SQL `WHERE` and the database does the filtering. The classic bug is calling `AsEnumerable()` or `ToList()` too early: everything after that runs in memory, so you pull the entire table across the wire and filter it client-side.

:material-file-document-outline: **Deep dive:** [E2 — `IEnumerable` vs `IQueryable`](../C-Sharp/csharp-linq.md#e2--ienumerable-vs-iqueryable)

---

### 15. What are delegates, `Func`/`Action`, and closures?

**Definition:** A **delegate** is a type-safe reference to a method. `Func`, `Action`, and `Predicate` are the built-in delegate shapes. A **closure** is a lambda that captures a variable from its enclosing scope.

**Detail:** `Action` returns void, `Func` returns a value, `Predicate` returns bool. The thing to know about closures: the lambda captures the **variable itself**, not a snapshot of its value. So a lambda created inside a `for` loop sees the loop variable's final value — `foreach` was fixed in C# 5, but `for` still behaves this way.

:material-file-document-outline: **Deep dive:** [E4 — Delegates](../C-Sharp/csharp-linq.md#e4--delegates-func--action--predicate) · [E5 — Lambdas & Closures](../C-Sharp/csharp-linq.md#e5--lambdas--closures)

## Async & Concurrency

### 16. What does `async`/`await` actually do?

**Definition:** `async` marks a method as one the compiler can rewrite so it can **pause and resume**. `await` is the pause point — it releases the thread while waiting and continues afterwards.

**Detail:** It is *not* multithreading. When you `await` an unfinished I/O operation, the thread is handed back to the pool to serve other work; often no thread is used at all while waiting. That buys throughput, not speed — one call doesn't get faster, but the app handles far more of them with fewer threads.

:material-file-document-outline: **Deep dive:** [F1 — async/await Model](../C-Sharp/csharp-async.md#f1--asyncawait-model)

---

### 17. What is the difference between `Task`, `Thread`, and `Parallel`?

**Definition:** A **`Thread`** is one operating-system thread. A **`Task`** is a unit of work, usually run on the thread pool. **`Parallel`/PLINQ** runs the same work over many items at once.

**Detail:** Threads are expensive to create and hold memory; tasks are cheap and composable. The rule for choosing: **I/O-bound work → `async`/`await`** (no thread needed while waiting); **CPU-bound work → `Task.Run` or `Parallel`** (you genuinely need cores).

:material-file-document-outline: **Deep dive:** [F5 — Threads vs Tasks vs Thread Pool](../C-Sharp/csharp-async.md#f5--threads-vs-tasks-vs-thread-pool) · [F8 — Parallel Programming](../C-Sharp/csharp-async.md#f8--parallel-programming-parallel-plinq)

---

### 18. Why do `.Result` and `.Wait()` deadlock?

**Definition:** A **deadlock** here happens when blocking on a task occupies the very context that the task's continuation needs in order to finish.

**Detail:** In classic ASP.NET, WinForms, and WPF there's a synchronization context that allows only one thread. `.Result` blocks it, then the awaited continuation queues up waiting for that same context — and neither can proceed. Fix: `await` all the way down. In library code, `ConfigureAwait(false)` tells the continuation not to capture the context at all.

:material-file-document-outline: **Deep dive:** [F3 — ConfigureAwait, Synchronization Context & Deadlocks](../C-Sharp/csharp-async.md#f3--configureawait-synchronization-context--deadlocks)

## Errors & Memory

### 19. What is the difference between `throw` and `throw ex`?

**Definition:** `throw` rethrows the current exception and **keeps its original stack trace**. `throw ex` throws it again but **resets the stack trace** to that line.

**Detail:** `throw ex` destroys the evidence — the log now points at your catch block instead of where the failure actually happened. Always use bare `throw`, or wrap it in a new exception passing the original as `InnerException`. Beyond that: catch specific exception types, never swallow silently, and clean up with `finally` or `using`.

:material-file-document-outline: **Deep dive:** [H2 — `throw` vs `throw ex`](../C-Sharp/csharp-exceptions.md#h2--rethrowing-throw-vs-throw-ex) · [H1 — try/catch/finally](../C-Sharp/csharp-exceptions.md#h1--trycatchfinally--exception-propagation)

---

### 20. How does garbage collection work, and when do you need `IDisposable`?

**Definition:** The **garbage collector** automatically frees managed objects that are no longer reachable. **`IDisposable`** is how you release things the GC doesn't manage — files, sockets, database connections.

**Detail:** The GC is generational: most objects die young in Gen0, survivors get promoted to Gen1 then Gen2, and large objects go on the Large Object Heap. It handles *memory* only, which is why unmanaged resources need `Dispose` — and `using` calls it for you even if an exception is thrown. Classic leaks: static collections that keep growing, and event handlers you never unsubscribe.

:material-file-document-outline: **Deep dive:** [G1 — Garbage Collection](../C-Sharp/csharp-memory.md#g1--garbage-collection) · [G2 — `IDisposable` & `using`](../C-Sharp/csharp-memory.md#g2--idisposable-using-dispose-pattern-finalizers) · [G3 — Memory Leaks](../C-Sharp/csharp-memory.md#g3--memory-leaks-in-managed-code)
